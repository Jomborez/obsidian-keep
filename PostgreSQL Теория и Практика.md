# 0.Базовые термины

Экземпляр (Кластер БД) -- это изолированная оболочка, со своими паролями, пользователями базами и т.д, каждый кластер слушает разные порты чтобы не конфликтовать с другим и полностью изолирован

Логи лежат по пути - `sudo cat /var/log/postgresql/postgresql-17-main.log`

Контрольные суммы посмотреть, только когда сервер остановлен --

bash

sudo ./pg_checksums -e -D /var/lib/postgresql/17/main #включить подсчёт

bash

sudo ./pg_checksums -c -D /var/lib/postgresql/17/main \# запросить подсчёт

Переменная ON_ERROR_ROLLBACK -- необходима в транзакциях к БД, когда мы ошиблись в одной команде у нас перед именем пользователя появляется !#, и вся транказция не будет завершена её можно будет только прервать, commit. Чтобы этого избежать можно включить переменную

sql

\set ON_ERROR_ROLLBACK on

с ней если мы ошиблись в команде транзакция продолжится.

В postgresql по умолчанию включён автокомит для одиночных команд, не начинающие с BEGIN;

1. Архитектура PostgreSQL
    

При выполнение запроса с клиента, сервер прежде чем отдать результат проверяет 4 правила:

Синтаксис команды

Правила ( есть ли у вас доступ и существует ли такая таблица)

Статистика (логи что я отдал клиенту тому-то)

И передача самих данных

Журнал WAL -- в случае сбоя оперативной памяти, потери кэша, например отключение электричества. Из журнал WAL можн восстановить.

Многоверсионность -- наличие нескольких версий одной и той же строки, путём снапшотов. Что интересно PostgreSQL складывает старые версии и новые в один каталог в ОС.

Два основных уровня изоляции ( всего их 4 )

Read Commited (работает по умолчанию в PostgreSQL) -- работает так если одновременно открыта транзакция и один делает запрос `select * from table;` и у него выводится только 1 строчка 52, но в другой транзакции кто то добавил ещё строку 66, и закомитил, и при следующим `select * from table;` он уже увидит не 1 строчку, а две хотя сам ещё не закомитил. При удалении таблицы если кто-то в другой транзакции просматривает `select * from table;` удалить не получится, пока транзакция не будет завершена на устройстве которая просматривает.

Repetable Read -- его главное отличие пока ты сам не завершишь свою транзакцию, изменения он никакие не увидит, как только прописал commit или rollback он увидит другие изменения.

Блокировки -- чтение строк никогда не блокируется.

Блокировка таблиц -- запрещают изменение и удаление таблиц пока с ней идёт работа.

Устанавливаются автоматически и снимаются при завершении транзакции, и можно установить вручную.

Статус транзацкии -- активна зафиксирована оборвана.

Служебная информация -- хранится на диске pgexact , внутри этого каталого файлики по 2 бита которые показывают статус.

2. Очистка
    

Есть ряд факторов которые надо переодически делать:

Очистка мёртвых строк ( старые перезаписанные версии которые не используются)

Обновление карты видимости ( чтобы не ходить в таблицу, а смотреть строки по индексам, в таком случае многоверсионность будет сохраняться, и мы будем игнорировать мёртвые строки)

Обновление статистки: показывает актуальное количество строк.

Заморозка -- У каждой транзакции в PostgreSQL есть номер --- **XID**. Он 32-битный. Считай, что это счётчик, который постоянно растёт: 1, 2, 3, ... и у него есть потолок --- примерно **4 миллиарда** (реально безопасный предел около 2 млрд).

Когда счётчик доходит до потолка, он **переполняется** и начинается заново с нуля. И вот тут беда.

**Заморозка (freeze)** --- это когда PostgreSQL говорит: «Эта строка старая, она была создана очень давно. Забудь про её номер транзакции, считай её **вечной и видимой всем всегда**.»

То есть строка как бы получает штамп **«сделано до начала времён»**. Её больше не нужно сравнивать с текущим счётчиком XID --- она всегда видима. И переполнение счётчика ей уже не страшно.

Чтобы не делать это ручками админу, ну это тупо нереально), создали два демона, один Autovacuum launcher -- он постоянно висит в процессах, можно на него посмотреть: `ps aux | grep "autovacuum launcher"`

он запускает autovacuum worker, и вот уже он делает ряд задач: очищает таблицы, замораживает, вообщем делает всё выше перечисленное.

# 1.Конфигурация СУБД

postgresql.conf -- Основной файл конфигруации определённого экзепляра и версии, находится по пути:  
`/etc/postgresql/<версия>/<кластер>/postgresql.conf`

Если он лежит в другом месте посмотреть можно внутри БД, командой:

sql

SHOW config_file;

при изменении параметров необходимо перечитать конфигруацию:

bash

pg_ctlcluster версия экземпляр reload

work_mem -- по умолчанию это значение 4096 КБ, этот параметр выделяет лимит на одну операцию, т.е для лёгких запросов это значение ещё куда не шло, но тяжелый запрос будет обрабываться долго, по дефолту лучше ставить 16-64 мб, можно изменить в nano или vim

bash

sudo nano /etc/postgresql/17/main/postgresql.conf

ini

work_mem = 16MB

Есть аналог postgresql.auto.conf, он имеет выше приоритет чем postgresql.conf, и более удобен, он проверяет базовые ошибки .

Например `ALTER SYSTEM SET work_mem = '14MB';`

После всех манипуляций, не забываем: `sudo pg_ctlcluster 17 main reload`

Проверить что применилось - `SHOW work_mem;`

max_connections -- сколько максимальных подключений разрешено к базе, по умолчанию значение 100, посмотреть можно :

sql

SHOW max_connections;

Изменить: `ALTER SYSTEM SET max_connections = '350';`

Важно: этот параметр применится только при перезапуске экземпляра, при перечитывании он не применится.

bash

sudo pg_ctlcluster 17 main restart

## 1.1 Базовая настройка PostgreSQL

Переходим в оболочку psql под суперпользователем.

bash

sudo -i -u postgres psql

к базе также можно подключиться другой командой:

bash

psql -d база -U пользователь -h адрес -p порт

Создадим пользователя и базу.

sql

CREATE USER test WITH PASSWORD 'test';
CREATE DATABASE test_db OWNER test;

Посмотреть всех пользователей: **\du**

Выходим из оболчки psql **\q**

И подключаемся нужным пользователем:

bash

psql -U test -d test_db -h 127.0.0.1

-h если это не локальная база указываем ip базы.

# Создание и заполнение таблицы.

sql

CREATE TABLE test ( id SERIAL PRIMARY KEY, name VARCHAR (20) NOT NULL, email VARCHAR (50) UNIQUE, age VARCHAR (50), date TIMESTAMP DEFAULT NOW() );

Создаём таблицу test.

|Команда|Пояснение|
|---|---|
|`CREATE TABLE test`|Создаём новую таблицу с именем test|
|`id SERIAL PRIMARY KEY`|Столбец id: тип SERIAL (автоинкрементное целое, PostgreSQL сам создаёт последовательность), PRIMARY KEY --- первичный ключ, уникальный и не NULL, по нему автоматически создаётся индекс|
|`name VARCHAR(20) NOT NULL`|Строка до 20 символов, NOT NULL --- обязательное поле, пустым быть не может|
|`email VARCHAR(50) UNIQUE`|Строка до 50 символов, UNIQUE --- все значения должны быть разными (создаётся уникальный индекс), но NULL допускается (и даже несколько NULL --- это особенность PostgreSQL)|
|`date TIMESTAMP DEFAULT NOW()`|Дата-время; если при вставке значение не указано, подставится NOW() --- текущий момент времени|

Добавим строки в нашу таблицу --

sql

INSERT INTO test (name, email, age) VALUES ('Иван', 'ivan@example.com', '15');

`SELECT * FROM test;`

_Выводим всю таблицу, в проде не использовать слишком много строк перегрузят бд!_

# Выборка записей с условиями

`SELECT * FROM имя таблицы;` # вывести все строки таблицы не рекомендуется в проде положит бд если много записей.

`SELECT id,name, email FROM test;`

Вывести определённые столбцы.

Добавить условие :

`SELECT id,name, email FROM test WHERE id>1;`

Ищем строки у которых в id > 1

`SELECT * FROM test WHERE name <> 'Bob' AND age > 20;`

Ищем строку где имя не равно Bob и одновременно возраст должен быть больше 20

`SELECT * FROM test WHERE age BETWEEN 10 and 50;`

_Ищем строку где в поле age диапазон от 10 до 50_

`SELECT * FROM test WHERE email LIKE 'ivan%';`

_Ищем строки где начинается с ivan, а дальше не важно._

_Также можно использовать команду NOT LIKE будет искаться всё кроме ivan%_

`SELECT id,name,age FROM test ORDER BY id DESC LIMIT 2;`

_Сортировка по убыванию и вывести только 2 записи_
